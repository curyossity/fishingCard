# UI-03 — detailed Catch Chain

Implemented the approved detailed Catch Chain as a reusable, data-bound component. The existing scene and build selection remain unchanged. Full comparison-scene installation belongs to UI-07; this delivery is the integrated chain component, not the finished gameplay screen.

## Delivered behavior

- `Prefabs/CatchChain.prefab` uses the shared `CatchChainView` entry point already called by `FishingRunController`. Its optional `CatchChainPresentation` reference selects `JournalCatchChainPresentation`; absent that reference, the original renderer remains active.
- The themed presenter reuses physical compact-card views and independent brass links. Refreshes update names, resolved Weight, role-aware Value and artwork without recreating listeners or resetting scrolling. Arbitrary attachment counts extend real masked ScrollRect content. Removing attachments clamps the remaining scroll range and hides surplus pooled views.
- Compact cards use CatchFrameV2 and exact stable-ID artwork mappings. The theme stores portrait bounds independently of gameplay definitions, including the approved 440 × 250 Crab framing and 552 × 221 fish framing. Missing art clears the slot rather than showing a different creature.
- Bait shows the cyan rounded border, inner etching and explicit badge, with zero haul Value. Catch preserves self-hidden Value behavior. Weight/Value fit within bounded fields, including zero and large modified values. Names retain reference title case in this theme; old prefabs retain uppercase and centered defaults.
- Hover/navigation focus, selection, disabled and legal-target feedback use separate native UI layers. These layers never recolor the parchment, creature or brass hardware. Existing controller callbacks and modal target-validation owners remain authoritative; the chain grants no new Release action.
- BrassConnectorV3 remains separate sibling artwork. Its measured eyelets align 14 reference pixels inside adjacent card edges; top/bottom hangers use the approved 104-pixel canvas height. Hardware scrolls with the cards. The heading remains outside the clipped content.
- The candidate canvas now contains the chain prefab and binds its sibling load meter. Meter capacity changes reuse aspect-preserved pips in fitted rows and receive effective load from the controller. No view sums base weights or decides overload consequences.

All theme-owned implementation remains under `Assets/UIThemes/MidnightFieldJournal/`. Only the generic presentation seam and backward-compatible compact-view extensions live with the shared views. No card definitions, old prefabs, old images, scenes or build settings were edited for this task.
