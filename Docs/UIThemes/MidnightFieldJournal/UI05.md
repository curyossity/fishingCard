# UI-05 — central creature and event cards

The isolated `CreatureCard.prefab` now uses the assembled Penpot field geometry, approved blank master and exact new-theme portraits. The shared view retains its existing controller API. Original gameplay definitions, scene, build settings and legacy visual assets remain unchanged; the candidate has not been installed into the active game.

Dynamic layers include type/title, resolved Weight/Value (including zero), portrait, separate ability names and descriptions, footer tags, existing one-to-four rarity hooks and Catch/Bait selection. Selection uses a hollow native border and restrained wash. New encounters default to Catch; refreshing the same card preserves its choice. The view only notifies the controller and never commits an attachment or executes an effect.

Events and locations use the single-panel event master. Stat labels and numbers, both role controls, ability headings, tags and rarity are suppressed. Creatures, treasures and Apex use the dual-panel face. Longer rules fit within their panels without changing source descriptions. Definition-owned color/size highlights and central portrait scale/rotation/offset remain supported.

Identity concealment removes portrait, species, rules, ability names, tags and rarity, displays unknown stats and keeps both roles selectable. Information-only concealment and self-hidden Value retain their distinct contracts. Blank/null/preview and event transitions clear old identity-bearing fields. These masks continue through existing transition/history callers; full gameplay flow verification remains UI-07.

The Penpot candidate omitted rarity. The implementation preserves its footer tag line and places native hook strokes immediately below it, retaining the game's existing count semantics. This treatment is documented in [the visual contract](VisualContract.md) and the captures for review; it is not presented as a new user-approved artwork revision. No old theme rail or icon dependency was introduced.

Rebuild through **Fishing Cards → UI → Midnight Field Journal → Build Reusable Templates**. **Validate Central Cards** performs disposable captures/checks. Play Mode input checks use `JournalCreatureCardChecks.StartPlayModeSmoke()`, one rendered frame, then `FinishPlayModeSmoke()`; the previous background-ticking setting is restored.

Component implementation is complete for the available source set, not final full-roster visual approval.
