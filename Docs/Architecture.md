# Deepwater — Architecture

Current responsibility map: Discover → Land → Build / Upgrade, updated 19 November 2026 for five-tag content and effect implementation. The [GDD](Fishing_Card_Roguelike_GDD_with_image/Fishing_Card_Roguelike_GDD.md) governs mechanics; [Architecture Implementation Reference](Architecture%20Implementation%20Reference.md) preserves historical implementation details. Five-tag preparation, one-tag content and removal of secondary-tag preference are implemented; see [current validation](Validation/FiveTagAbilities/README.md).

## Ownership

| Owner | Responsibility |
| --- | --- |
| FishingRunController | Expedition phase, accepted creature occurrence, landing commands/outcomes, placement commitment, automatic duplicate resolution, continuation and exactly-once settlement |
| EncounterRuntime / slot runtime | Four prepared symbols chosen from five tags, three reels, one optional respin, explicit acceptance, eligible biome creature selection and occurrence identity |
| SlotCreatureSelector / SlotSelectionSettings | Separate rarity roll, tag guarantees, lower-tier nearest-rarity ties and unlock/Apex eligibility; no preference from a pair's unmatched symbol |
| LandingChallengeRuntime / LandingSettings | Absolute-clock motion, accuracy, points, attempts, protected Misses, feedback freeze and immediate success/failure |
| LandingScoring / LandingRigMember / LandingRigRule | Frozen committed-species/tag/level scoring, flat bonuses before multiplier products, explicit Miss rules and source attribution |
| RigRuntime | One ordered position per species, levels/copies, legal insertion, pure transactional previews, upgrades, removal, triggers, derived sale values and haul snapshots |
| CardDefinition / CreatureAbilityDefinition | Species content authority: identity, sprites, exactly one creature tag, base price, one primary-ability blueprint, descriptions, tuning and level progression; no expedition mutations |
| CardInstance | Stable runtime member identity, effective tags, temporary level/copies, frozen ability, completed value grants and current sale value |
| Progression / results | Permanent unlock/reward ownership under approved predicates; resolved full-haul snapshot before temporary rig cleanup |
| Views | Render authoritative state and forward occurrence/revision-bound commands; never decide score, legal placement or rewards |
| Editor authoring | Validate one supported tag and one primary ability per creature, effect-handler support, definitions and tuning; import approved sprites, create reusable phase prefabs and preserve scene/Harbor bindings |

## Phase and transaction boundaries

Every expedition begins in Shallows with an empty rig. Discover prepares four of five tags as active symbols and retains one optional lock/respin, keeping the final result visible until Accept Tags. A pair guarantees its repeated tag without a preference from the unmatched symbol. Creature selection creates the Landing occurrence without acquisition.

Harbor Set Sail opens `SlotTagPreparationView` on an independent Tackle canvas. It owns only a local four-of-five draft and forwards explicit commitment to the controller before the Harbor starts the expedition. `TackleTagPreparationPresentation` renders the existing reel illustrations, shared tag philosophies, selected lamps, readiness and start failures. Cancel discards the draft and restores Harbor input/focus; repeated open requests preserve an open draft. `JournalHarborFlow.SlotPreparation` is the explicit scene binding, independent of the Harbor hierarchy or theme. `TackleTagPreparationSetup` authors the GUID-stable preparation prefab and rebinds its root canvas during scene/Harbor regeneration. See [preparation design](UIThemes/TackleApparatusConcept/TagPreparation/README.md) and [validation](Validation/TagPreparation/README.md).

The GDD owns tag philosophies and shared mechanics. Editable creature definitions own species tags and primary abilities; Markdown does not duplicate the roster or per-species effect catalog. `RigAbilityText` resolves authored description tokens against current-level amounts for both card text and Build. Landing owns encounter-local sequences, per-rule trigger usage, encounter tag/rarity, assistance and strike resolution; the rig owner retains acquisition/upgrade grants and continuous positional/value recalculation. Fixed-grid fish-time integration preserves deterministic conditional slowing without changing the zone clock. Attempt grants retain source attribution in strike feedback. See [Creature Ability Authoring](Creature%20Ability%20Design.md) for supported handlers, shared contracts and assistance stacking.

Land captures only committed members, primary ability levels and effective tags. New acquisitions cannot assist their own challenge. Success reserves the landed species for Build; failure snapshots and pays the full accumulated haul once, excludes the failed creature, then clears every temporary member, level and copy. Permanent progression remains preserved. `FishingRunResult.RewardClaimed` prevents repeated payout.

A new species receives a side-effect-free placement preview and one explicit legal-gap commitment. A duplicate automatically upgrades its existing position with no placement prompt. Every landed copy contributes its base sale value. Continuous value effects derive from accumulated species value; acquisition and upgrade triggers are distinct. Existing relative order is preserved. No manual reorder, Catch/Bait, capacity or overload action participates in the redesigned run.

Rig mutations validate on independent candidate snapshots before replacing live state. Stale Build occurrences/rig revisions, invalid authoring, blocked gaps and arithmetic overflow cannot partially acquire a creature. Controller notifications follow authoritative commitment. Previews publish no acquisition effects. Removal is a gameplay-owner operation for explicitly defined effects, not a manual UI action; current removal preserves collected base value/completed grants and recalculates continuous effects.

`RigBuildingView` owns selection, native navigation, previews and committed placement/upgrade feedback; `RigBuildingSetup` authors its separate Tackle canvas and binds it to `FishingRunView`. Its reusable cabinet/rail card prefabs retain independent faces, portraits and live labels. `TackleRigCardView` displays level and accumulated sale value. `RigAcquisitionReceipt` freezes independent before/after member snapshots, the acquired member and prior level/haul independently of the next encounter. The controller commits and continues once, blocks commands through `RigAcquisitionFeedbackVisible`, and accepts only the matching feedback occurrence for dismissal. The view releases placement feedback after 1.05 seconds (flight, then the haul count-up) and automatic upgrade feedback after 1.8 seconds on an unscaled clock; no extra confirmation is introduced. Disabled views release their receipt, and a controller-owned four-second deadline bounds interruptions. Discover remains hidden throughout either receipt. `LandingChallengeView` hides after successful landing. `SlotMachineSetup` retains all three phase bindings during regeneration.

`RigRuntime.ProjectEffects` reuses gameplay's positional counting on independent snapshots to expose continuous/strike coefficients, including inactive zeroes, without firing effects or predicting conditions. `RigBuildChange` compares these projections, sale values and positional identities for existing members. `RigBuildPresentation` pools the non-intercepting ghost, follows visible faces with external consequence captions, eases neighbors apart and owns committed card flight, clip/rope settling, upgrade emphasis and routed sound. It respects shared sound/reduced-motion preferences and restores transforms on interruption. `RigBuildPolishSetup` preserves these bindings during full Build authoring. Last-strike information is quieter during placement and hidden while the receipt occupies its message band. See [Build polish validation](Validation/BuildPolish/README.md).

`RigRuntime.InspectAbility` derives read-only positional supporters and continuous value recipients from committed or insertion-preview snapshots using the same count/target logic as gameplay. `RigAbilityLinks` carries those identities; it predicts no strike conditions and repeats no completed acquisition grants. `RigCombinationPreview` owns Build tray inspection: gold for the inspected creature, green for current supporters/recipients and red for committed links disconnected by the selected insertion. It follows `TackleCardTooltip` pointer/focus/dismissal state and pools external non-intercepting halos through `RigRelationshipGlow`, a feathered vertex-alpha mesh with a transparent center. It checks tray visibility and identifies a newly landed supporter at its ghost face, falling back to the encounter portrait without a ghost. The tooltip names relationships, explains color roles and includes full model-derived placement changes while retaining conditional-trigger caveats. `RigCombinationPreviewSetup`, retained by tooltip/Build regeneration, authors only the Build bindings and native layer. See [combination-preview validation](Validation/RigCombinationPreview/README.md).

The exporter permits independent AssetLibrary image layers and an explicit whole-file copy of the integrated housing. `RigAbilityText` formats current-level authored effects; `TackleBuildTypography` aligns native glyph ink. This prepares a fixed shell for future transitions without adding a transition or changing rules. See [Landing source](UIThemes/TackleApparatusConcept/LandingIntegrated/README.md) and [validation](Validation/LandingIntegrated/README.md).

Discover's 18 November variants retain the same outside shell with a recessed wheel bay and integrated lock-control deck. `TackleDiscoverHousingSetup` imports the normalized whole housing, retaining the wheels' native projection coordinates. The current original-size variant uses the original 320 × 365 wheel dimensions and 100% scale, registered to the new housing’s measured socket centers; its enlarged interior removes the crossmember. The compact variant retains 72% wheel scale. Selection lives in a project JSON asset and survives full Discover regeneration. Menus switch between original-size/compact unified versions or restore the original machine. Both previous functional prefabs and sprite sources remain preserved. `TackleDiscoverHousingChecks` independently compares all three runtime PNG silhouettes, protected exterior pixels and stage transforms, plus the retained original composition and original-size wheel transforms. See [current source and version menus](UIThemes/TackleApparatusConcept/DiscoverIntegrated/FullSize/README.md) and [validation](Validation/DiscoverIntegrated/FullSize/README.md).

The effects well has no progress trough. `RigBuildingSetup` removes `build-portrait`/`build-effect` overlay assets after replacing their prefab references; portrait and level/value/effect text remain native. `RigBuildingView` derives ability-scroll dimensions from its viewport. Pixel checks compare the frame geometry with Landing and verify unchanged artwork outside the upper working area. The insertion heading sits below both borders. See [frame provenance](UIThemes/TackleApparatusConcept/BuildUpgradeRevision/IntegratedMachine/FramesV2/README.md).

Biome completion predicates, final success endpoints, permanent grant tables, no-legal-position resolution and finalized species abilities remain design inputs. Authored special Apex encounters retain eligibility and are routed through Landing; Build does not invent an automatic completion reward or a new gate.

## Presentation and validation

`LandingCardCollision` also owns a synchronized 55 ms white contact flash on both machine panels. Each `LandingPanelFlash` is a non-intercepting, topmost child that draws the existing panel silhouette in white, covering its artwork and live fields without rectangular crop corners. Its 12 ms full-white attack and short fade use mapped real time, so final-hit slow motion cannot stretch the flash. Reduced motion, quiet misses, handoffs and all collision cleanup paths clear it. `LandingCardCollisionSetup` preserves both authored layers through regeneration. See [impact-flash validation](Validation/ImpactFlash/README.md).

Landing point readouts, Resistance labels and last-hit totals use `LandingScoreRush.Format`, which rounds upward to a whole point for display before applying the existing large-number abbreviations. `FormatMultiplier` preserves fractional factors. The resolved decimal score, progress ratio, target comparison and inspectable arithmetic retain their original precision; this is a presentation policy, not an additional scoring operation.

Landing scoring freezes each contribution's current-level explanation and positional enabler identities alongside its exact bonus/multiplier/attempt grant. `FishingRunController.LastLandingStrike` captures committed pre-acquisition members, accumulated points and Resistance before terminal handling, survives continuation and failure cleanup, and clears at the next expedition start. `LandingStrikeFeedback` owns persistent source portraits, ordered addition/multiplier rows and ongoing assistance. `LandingContributionView` supplies pointer/native-focus explanations through the shared tooltip; `LandingActivationView` draws non-intercepting source/support outlines outside card faces and scroll masks. Build consumes the frozen winning receipt without replaying its celebration. `LandingStrikeFeedbackSetup` preserves these bindings in both phase-generation paths. See [strike-feedback validation](Validation/LandingStrikeFeedback/README.md).

`LandingScoreSequence` derives a bounded collision schedule from already resolved operations. `LandingScoreRush` owns exact score delivery, contributor identity in the machine slot, synchronized existing audio and transfer into accumulated progress. The 24 November collision treatment replaces projectile delivery: `LandingCardCollision` owns the creature and score panel transforms and emits the visual-stage shake signal. It samples a backward windup with late horizontal squash, directional dash stretch, compressed 75–105 ms contact and one restrained recovery overshoot. The creature preserves apparent area; the score card keeps its rigid shape and directional recoil. Rest scales are captured with transforms, and leading-edge compensation keeps deformation on the existing trajectory and planted at impact. The collision supplies a shake signal to the overlay camera owner; the world camera, normalized aiming state, rig cards and game time remain untouched.

`LandingCollisionGraphic` renders the original fixed housing around a continuous dark recess. Each moving face now references a separate `LandingPanelArtwork` asset: a native sprite slice and an eight-point beveled silhouette. The renderer leaves all pixels outside that silhouette undrawn, removing the rectangular cabinet surround during travel, deformation, turns and zoom. Both independent sprites share the unchanged original texture, preserving source-pixel registration without duplicate image memory or a redraw. `LandingPanelArtworkSetup` creates missing assets and preserves existing authored shapes and GUIDs on regeneration; the old rectangular path remains only for historical prefab compatibility. `LandingCardCollisionSetup`, retained by `LandingScoreRushSetup`, groups the existing portrait/tag fields and score/progress/readout fields with their respective faces, preserving references and reference-pixel placement. Both card faces use 88% scale and centers separated by an additional 24 reference pixels; contact distance derives from their actual scaled bounds. A continuous dark recess fills the newly visible space. Header attribution remains in its existing name band. Regeneration is idempotent. See [separated-panel validation and comparison](Validation/SeparatedPanels/README.md).

The first scoring base contact is at 301.6 ms. With scoring contributors, a single 140 ms entry turn begins at 600 ms and the first modifier starts preparation at 0.74 seconds. A matching 140 ms return turn follows the last complete rebound, before payout. Modifier dashes last 100–130 ms, with a 500 ms per-beat floor. Collision steps retain a 4.76-second budget independently of the two 140 ms boundaries; complete feedback remains below the shared 7.5-second bound. Rigs without scoring contributors retain their previous timing. Zero-point misses retain their short quiet schedule. Numerical and existing impact-sound delivery share the physical contact timestamp. Strength follows actual relative growth and gained points, without evaluating abilities. Ordinary zero-point Misses do not collide. Reduced motion retains exact values and identities without card displacement or shake. Skip, completion, receipt replacement, independent disable and phase exit restore all owned transforms. `LandingRushGraphic` and `LandingStrikeContact` remain available for historical prefab compatibility but emit no projectile, burst, ribbon or particle geometry in this treatment. See [current collision validation and previews](Validation/ImpactCamera/README.md).

`LandingImpactTiming` maps canonical presentation time to wall time for only the final creature impact, provided its delivered-gain strength reaches .75. Earlier impacts never receive camera focus or slow motion, even if stronger; a weak final impact has no earlier-hit fallback. The final 30 ms of canonical dash, compressed contact hold and first 25 ms of rebound run at 28% presentation speed. The approach extension is capped at 30% of dash time; the rebound extension is capped at one quarter of return time. Preparation, launch, remaining recovery and all earlier hits retain normal speed. Its reversible mapping shares the 7.5-second bound. `LandingScoreRush` samples canonical visual time from an unscaled wall clock, while sound events store mapped real deadlines and the travel cue fits the mapped launch-to-impact duration. `FishingRunController` uses the same mapped duration for the cosmetic feedback gate. Score resolution, terminal handling and Unity time scale are unchanged.

`LandingImpactCamera` exclusively owns the overlay stage's scale/position, composing the collision's shake signal after card poses are sampled. It captures stable two-card contact bounds, pushes in over 70 ms to at most 1.65x zoom, fits both cards to the viewport, holds through slow contact and initial rebound, then eases out over up to 220 ms of normal-speed recovery. It adds no hierarchy wrapper or world-camera transform. `LandingCardCollision` retains a historical serialized stage reference for tool compatibility but no longer writes it. Normal hits keep their original view and pace. Reduced motion restores the unzoomed stage immediately and retains mapped readable pacing. Skip, replacement, completion, independent disable and phase exit restore stage scale/position. Existing visual effects, including the canonical two-thirds-second water drain, share the slowed visual clock.

`LandingWaterImpact` owns custom PixelFX water-atlas playback and native score-digit punch on the existing unscaled collision clock. `LandingCardCollision.ContactPoint` exposes the moving receiver seam; a non-intercepting RawImage follows it without moving either card. Three authored sheet tiers follow the existing delivered-gain strength. Spray begins exactly at a positive score delivery, lasts up to 400 ms, and clears at a handoff/new preparation so an older hit cannot return after a flip. The digit-only punch settles in 160 ms; the score panel remains rigid. Reduced motion, skip, replacement, independent disable and phase exit restore the number and hide the layer. `LandingWaterImpactSetup`, retained by `LandingCardCollisionSetup`, reads maintained PixelFX export metadata for point-filtered uncompressed atlases and stable native bindings. Source recipes, export metadata and provenance live under `Tools/PixelFX`; supplied artwork, scoring and sound assets are unchanged. Larger ripples and dash wakes are separate optional additions.

`LandingCombatCardsSetup` gives the two moving Landing cards fixed sides. The left mover (the collision's `creatureCard`) is the player's **Strike gauge**. The right receiver (`scoreCard`) is the encounter creature's **specimen plate**. The right card holds the encounter portrait, its tag and a Resistance gauge that drains: `TackleLandingPresentation` writes the remaining Resistance and a fill of `1 − points / Resistance`. The left card holds the score readout (grade in the tab, running damage in the window). `LandingScoringPortrait` now stages contributors in a dedicated left portrait, label and detail line instead of the creature's identity, so the header keeps the creature's name. `LandingStrikePanel` owns the idle state (hook, READY or the challenge verdict, the frozen accuracy bases from `LandingChallengeRuntime.GoodPoints`/`PerfectPoints`), the label, and the number's placement beside contributors on `LandingScoringPortrait.Changed`. The entrance, rarity banner, outcome beats, payout readout and damage reaction bind to the right card through the setup's `CreatureCard`/`CreatureFade`/`CreatureFlash` helpers. Collision roles are unchanged, so every ram is the player's side hitting the creature. The machine is drawn from `landing-machine-empty.png`, the original art with its two painted panels erased by `Tools/Art/make_empty_landing_machine.py`. The cards therefore rest on the machine's own recess, and the old collision housing, with its flat dark block where those panels were, is disabled. `LandingOutcome.behindCard` keeps the recess's assistance readouts hidden while an escaped creature's card is gone. See [combat-card validation](Validation/CombatCards/README.md).

`LandingDamageNumbers` shows a strike's arithmetic on the creature's side. The Strike panel shows only the attacker: the hook and grade for the accuracy hit, or the contributing rig creature with its name and level. At every ram, the hit's own effect (+base, +addition, ×multiplier) pops out of the impact point as an outlined floating number, coloured by kind, sized by step strength, rising and fanning out before it fades. A DAMAGE counter above the creature card follows the running total and drops into the Resistance bar in the 0.16 s before the payout. Everything is sampled statelessly from the score sequence; reduced motion removes drift, pop and flight. `LandingDamageNumbersSetup`, retained by score-rush and combat-card authoring, builds the layer, the pooled template, the counter and the outline material. See [damage-number validation](Validation/DamageNumbers/README.md).

`LandingDamageFeedback` makes the score payout read as damage to the encounter creature. For 0.36 s from `PayoutAt`, it knocks the creature card away from the Strike panel with a shake, tilt and squash, flashes a red hurt tint through `LandingPanelFlash.Show(opacity, tint)`, and thrashes the held fish in the timing glass. The Resistance bar then plays `LandingHealthTrail`: the red fill eases down to the new value while a white trail holds the old one; after a 0.15 s hold the trail eases down until it meets the red. A damaging strike's feedback, and so the controller gate, lasts until the trail settles (`LandingScoreSequence.Duration` = payout + `LandingHealthTrail.Tail`), so control never returns while the bar is moving. Severity follows the share of Resistance dealt, with a floor for any damage and a lift for the finishing blow. Zero-point strikes get nothing. `LandingScoreRush` renders it right after the collision, which resets the card each frame, so the reaction composes rather than accumulates; it clears on finish. Reduced motion keeps only a softer tint and the chip. `LandingDamageFeedbackSetup`, retained by score-rush authoring, authors the chip and bindings. See [damage-feedback validation](Validation/DamageFeedback/README.md).

`LandingStrikeWater` renders a separate masked water level inside the timing glass, as the first child beneath the existing fish and accuracy bands. It samples canonical delivered strike totals against half the frozen receipt Resistance, saturating at full; previous attempts are excluded and intermediate subtotals are not counted twice. The water rises over 65 ms at each contact, stays through contributor turns, then begins one two-thirds-second drain 80 ms after the final delivery. Its bounded native mesh of at most 656 vertices and small surface wave use the existing unscaled clock, without textures, transient objects, aiming changes or new model state. Body and foam are clipped to the eight-sided glass floor/roof with 18-pixel corner cuts; exact segment splits and surface intersections keep full and partial fills off the brass frame. Reduced motion uses a flat surface and immediate contact updates while retaining the drain. `LandingScoreRush` clears it on new receipts, skip, completion and phase exit; independent disable also empties it. `LandingStrikeWaterSetup`, retained by score-rush authoring, preserves the track mask, four-pixel inset and non-interacting layering.

`LandingScoringPortrait` snapshots the encounter portrait/name/tags. Each committed contributor temporarily occupies the machine card; grouped beats retain all identities inside that same face. `LandingCardHandoff.Frame` supplies deterministic global progress, per-turn face phase, turn count and visible source index. Strike-to-rig and rig-to-strike boundaries on the Strike panel use one vertical turn of 140 ms, the same as a change between contributors (the encounter creature has its own card, so no longer turn is needed to tell them apart); identity changes once at the hidden midpoint. The first source has no additional ordinary turn. Between different contributors, a single 140 ms turn remains inside preparation (shortened to at most 60% of available windup for grouped beats); unchanged consecutive identities skip it. `LandingScoreRush` swaps portrait/name/tag/operation/source attribution together. `LandingCardCollision` projects/fades the enclosing frame/portrait/tag CanvasGroup while leaving the score panel steady. External name and operation fade at the identity swap. Reduced motion uses one stationary fade per boundary rather than repeated flicker. The original encounter returns during the final boundary, or immediately on termination. `LandingScoringPortrait` restores captured header opacity along with the encounter identity. Score, sound and collision deadlines use the same adjusted sequence; gameplay rules remain in existing controller/model owners.

`TacklePhaseTransition` replaces the hard cut between Discover, Landing and Build with a roller shutter. At the start of each view refresh, `FishingRunView.PreparePhaseChange` compares the visible Tackle canvas with the one the views will show, using each view's `WouldShow` (the same rule its `Present` applies). On a change it renders the outgoing canvas once into a screen-sized texture and holds it on an overlay canvas (sorting order 450, between Landing and Harbor preparation). `TackleShutterGraphic` then drops a slatted shutter over the whole machine body, with a regular chamfered outline measured from the shared housing (pipes, knobs and side bulges stay outside it) and bent over a hidden drum behind the cabinet's top edge, lands with a small rebound and jolt, the held frame is removed while the window is covered, and the shutter rolls back up over the new phase. It lasts 0.48 s on the unscaled clock (0.2 s crossfade with reduced motion), blocks pointer input while visible, and never gates commands or outcomes. `BeginSelectedLanding` offsets the creature entrance by `PhaseTransitionLead`, so the reveal starts as the shutter rises. Harbor entry and expedition endings still cut directly. `TacklePhaseTransitionSetup` authors the overlay prefab and binds it during scene regeneration. See [phase-transition validation](Validation/PhaseTransitions/README.md).

The controller also owns the skippable `LandingRevealPending` gate for the encounter creature's entrance. `BeginSelectedLanding` records `LandingRevealStartedAt` and a deadline from `LandingRevealTiming.For(rarity).Duration` only when a view can present it; while pending, `HoldPresentationClock` keeps the fish and zone still and `TryStrikeLanding` rejects strikes. Space/Strike calls `CompleteLandingReveal`, which consumes that input frame so it cannot also strike. `LandingRevealTiming` is the pure rarity table (Common one quick turn; Uncommon two; Rare and Legendary add machine anticipation, three accelerating turns, one panel flash and a stage impulse; all under 1.3 seconds). `LandingCreatureReveal` samples it from the controller's start time, sharing the collision's creature panel, fade and flash and composing its stage offset through `LandingImpactCamera.RenderOffset`. It plays the existing Reveal cue once, pitched and levelled by rarity, and restores every pose on completion, skip, disable or phase exit. Reduced motion keeps one stationary fade. The message band shows only `SPACE TO SKIP` during the entrance; rarity is never written there. Rare and Legendary creatures get `LandingRarityBanner`, a native-geometry tag stamped across the lower creature card when the face lands (or immediately on skip): the strike ribbon's brass/stud/swallowtail construction with a dark enamel face (teal Rare, black-gold Legendary) so it cannot read as a score, plus four studs echoing the card faces' rarity hooks (3 or 4 lit). It slams in, tilts to -4 degrees, holds about one second after the gate ends, then folds away with the card-turn language; Legendary adds one glint. It never covers the timing track, and the presentation clears it when strike feedback begins, on failure, on a new encounter or at phase exit. Reduced motion fades it in and out. Common and Uncommon have no banner. `LandingCreatureRevealSetup`, retained by score-rush authoring, binds these owners. Editor-only `PreviewLandingReveal` and **Fishing Cards → Preview → Creature Reveal** replay any rarity for review. See [creature-reveal validation](Validation/CreatureReveal/README.md).

The controller also owns the skippable `LandingOutcomePending` gate, which follows score feedback on a terminal strike (or the strike itself without a score presentation). Outcomes, the failure payout and rig cleanup have already resolved; only the duplicate auto-upgrade (`ContinueAfterLandingOutcome`), Build and the Harbor return wait for it, and its deadline is `LandingOutcomeTiming.Duration`. `LandingOutcomeTiming` is the pure schedule. Landed (0.95 s): the creature card dips, is yanked up and slams home with a flash, stage impulse and a LANDED stamp, then the shutter opens Build. Escaped: the card thrashes and sinks out of its frame under an ESCAPED stamp, the header changes from `<CREATURE> ESCAPED` to `EXPEDITION OVER`, and each creature in the paid haul (`LastHaul`) cashes out in order into a HAUL PAID readout in the empty frame (0.03–0.22 s per creature within a 1.6 s budget), ending exactly on `LastHaulValue` before the rig column clears and Return to Harbor appears. `LandingOutcome` samples the controller's start time, owns the creature panel, flash, stage offset, payout readout and cashed-out card fades while it plays, and restores them on new encounters, Harbor return and phase exit. Space or SKIP ends it early. Reduced motion keeps fades and numbers without card motion. The outcome stamp is a second `LandingRarityBanner` instance using its outcome styles (green LANDED, rust ESCAPED, no rarity studs). `LandingOutcomeSetup`, retained by score-rush authoring, binds these layers. Build's `RigBuildingView` rolls the haul plaque and HAUL CHANGE readout from the receipt's previous haul to its committed haul (`TackleHaulCount`), after the placement flight lands or straight away for an upgrade, ticking as it climbs and punching on arrival. The placement receipt now lasts 1.05 s. See [outcome validation](Validation/LandingOutcome/README.md).

The controller owns the skippable `LandingFeedbackPending` gate. Points and terminal outcomes resolve immediately; failure immediately pays the full haul and clears the rig, while frozen source members remain visible during feedback. `HoldPresentationClock` excludes the count-up from motion, and controller commands reject a second strike or early placement. After feedback or Space/Finish, and then the outcome beat, a reserved duplicate upgrades automatically once, or a new species opens Build. Without an enabled score presentation there is no wait. The controller's bounded deadline prevents interrupted visuals from retaining the gate. See [score-rush validation](Validation/LandingScoreRush/README.md).
