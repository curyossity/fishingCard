# Explicit Catch/Bait selection

Creature and Apex encounters now start with neither panel selected. The controller rejects Descend until the player explicitly chooses Catch or Bait for the current encounter occurrence. Role-panel input remains enabled while Descend is unavailable. Switching roles updates the preview and authorizes only the final chosen role. The choice survives ordinary refreshes, but a new reveal/replacement, even of the same species, invalidates it. Stale occurrence IDs and None are rejected by the programmatic selection endpoint.

`CardDefinition.RequiresAttachmentChoice` identifies creature/Apex cards. `FishingRunController.TryChooseEncounterRole` owns selection tied to EncounterRuntime.EncounterRevision; CanDescend and attachment commitment use that state rather than a view fallback. The view mirrors controller state silently and keeps role-input readiness separate from Descend readiness. None=-1 preserves existing Catch=0/Bait=1 enum values. Existing treasure behavior is preserved; boat, empty/skipped and event encounters do not gain a choice gate. Surface and Techniques remain governed by their existing rules.
